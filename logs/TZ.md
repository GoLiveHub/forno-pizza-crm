# ТЕХНІЧНЕ ЗАВДАННЯ — "Forno Pizza" (повний текст, збережено 2026-08-08)

> Збережено дослівно з промпту замовника (версія 2.0 з логуванням і тестуванням).
> Це єдине джерело вимог. Етапи — розділ 6, правила роботи — розділ 7, журнал — розділ 9.

## 1. ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА

- Проект — **демонстрационная система для сети пиццерий** (один филиал в демке, с возможностью масштабирования).
- Две части:
  1. **Сайт-витрина** (для клиентов) — папка `site/`.
  2. **CRM-касса** (для сотрудников) — корневая папка `pizzacrm/`.
- Для портфолио: данные вымышленные, внешние интеграции (платежи, реальные API доставки) не требуются. Главное — работоспособный, красивый и функциональный продукт.

**Стек:**
- Бэкенд: PHP 8.4 (без фреймворка, файлы в `api/`).
- БД: SQLite (`data/crm.db`).
- Фронтенд: HTML, CSS, чистый JS (без фреймворков), SPA.
- Локализация: украинский/русский через `i18n.js` (в CRM и в витрине), язык в `localStorage`.
- CSS свой, без сторонних библиотек (кроме иконок, напр. Font Awesome).

## 3. ТРЕБОВАНИЯ К ФУНКЦИОНАЛУ

### 3.1. Управление заказами (ядро CRM)
- **Создание заказа:**
  - Офлайн (кассир): имя (опц., по умолч. "Гість"/"Гость"), способ получения (самовывоз/доставка), адрес и телефон (если доставка), выбор курьера из свободных (или автоназначение), позиции из меню с кастомизацией, промокод, оплата (наличные/карта — для демки выбор). Время готовки автоматически (15 мин на пиццу + 5 мин на каждую доп. позицию).
  - Онлайн (сайт): клиент заполняет поля, заказ в CRM со статусом "Новый", отображается на КДС. Кассир/менеджер подтверждает (кнопка "Підтвердити"/"Подтвердить") → статус "На кухні"/"На кухне".
- **Статусы (в CRM):**
  1. Прийнятий (Принят) — создан, не передан на кухню.
  2. На кухні (На кухне) — передан поварам.
  3. Готується (Готовится) — повар начал готовить.
  4. Готовий (Готов) — повар нажал "Готово".
  5. Очікує кур'єра (Ожидает курьера) — для доставки, заказ готов.
  6. В дорозі (В пути) — курьер забрал.
  7. Доставлений (Доставлен) / Виданий (Выдан) — финал.
  8. Скасований (Отменён) — с причиной.
  - Для клиента на сайте упрощённые: "Прийнятий", "Готується", "В дорозі", "Доставлений о [час]", "Скасований".
- **Нумерация:** `[Буква филиала][порядковый номер за день]` (напр. `F001`). Демо-филиал `F` (Forno). Сброс каждый день или просто увеличение. Поле `short_id` в таблице `orders`.
- **Редактирование и отмена:** редактировать (добавлять/убирать позиции) — кассир/менеджер до статуса "Готується". Отменять — кассир/менеджер/оператор поддержки (обязательно причина из выпадающего списка). Автоотмена: долго висит "Готовий" (>30 мин для самовывоза) или "Очікує кур'єра" (>20 мин) — система предлагает отменить или переназначить.

### 3.2. Меню и кастомизация
- Категории (Пиццы, Закуски, Напитки, Десерты). У блюда: название, описание, фото (заглушки), цена для каждого размера (30 и 40 см), ингредиенты, флаг доступности.
- Кастомизация пиццы (CRM и сайт):
  - Размер (30/40 см) — цена меняется.
  - Тесто (тонкое/пышное) — без изменения цены.
  - Ингредиенты: стандартные отмечены чекбоксами (включены). Можно убрать (бесплатно) или добавить доп. (платно, цена за ингредиент в настройках). Тесто — отдельно.
- Управление меню (менеджер/владелец): CRUD блюд, категорий, ингредиентов. Временно скрыть блюдо (недоступно).

### 3.3. Скидки и промокоды
- Раздел "Скидки". Типы: процент на весь заказ, фиксированная сумма, бесплатная доставка. Условия: минимальная сумма, срок действия, количество использований.
- Проверка и применение (CRM и сайт). Для демки 2–3 предустановленных промокода (напр. `WELCOME10` – 10%).

### 3.4. Клиентская база
- При создании заказа (офлайн/онлайн) при наличии телефона клиент ищется/создаётся. Профиль: имя, телефон, адреса (несколько), история заказов, сумма покупок, количество заказов.
- В CRM — список клиентов с поиском, просмотр истории.
- Лояльность (опционально): бонусные баллы (5% от суммы) — скидка при следующем заказе (упрощённо).

### 3.5. Кухонный дисплей (KDS) — отдельная страница
- Отдельный HTML-файл (напр. `kds.html`) в корне CRM, доступен только роли "Повар".
- Заказы со статусами "На кухні" и "Готується" в виде карточек: номер, блюда (размеры, кастомизация), таймер с момента создания.
- Цвета: жёлтый — ждёт начала ("На кухні"), оранжевый — готовится ("Готується"), зелёный — готово (блок "Готово до видачі").
- Кнопка "Почати готувати" → "Готується". Кнопка "Готово" → "Готовий", заказ исчезает из основного списка, появляется в готовых.
- Звуковое оповещение при новом заказе (Web Audio API — простой писк).
- Тёмная тема (фон #1e1e1e, акценты яркие) — отдельный `kds.css` или инлайн, НЕ трогать `app.css`.
- Автообновление каждые 3 сек через `fetch` к `api/orders.php?status=active`.

### 3.6. Курьерский модуль
- Раздел "Кур'єри" — список курьеров со статусом (вільний/зайнятий).
- При создании заказа с доставкой кассир выбирает свободного курьера или автоназначение (по очереди).
- Курьер видит свой список заказов (отдельная страница/дашборд) со статусами "Очікує кур'єра" и "В дорозі".
- Уведомление курьеру (всплывающее окно, звук). "Забрав" → "В дорозі". По прибытии → "Доставлений".
- Время доставки фиксируется для отчётов.

### 3.7. Сайт-витрина (для клиентов)
- Главная: баннер с акцией, популярные пиццы, преимущества.
- Меню: категории, карточки (фото, цена, краткое описание). Клик — модалка с кастомизацией и добавлением в корзину.
- Корзина: позиции, изменение количества, удаление, промокод, итог.
- Оформление: форма (имя, телефон, адрес, комментарий), самовывоз/доставка. После отправки — номер заказа и статус (трекинг).
- Личный кабинет (опционально): регистрация/вход (без реальной почты), история заказов, избранное.
- Чат поддержки: иконка в углу, окно чата. Сообщения в БД (`messages`), отображаются оператору в CRM. `setInterval` (имитация real-time).
- Дизайн адаптивный, тёплые тона (красный/оранжевый/бежевый). Вёрстка начата — добавлять функционал, не ломая существующий CSS.

### 3.8. Чат поддержки (в CRM)
- Раздел "Чаты" для оператора. Список клиентов, писавших. При клике — переписка.
- Оператор видит новые сообщения, отвечает. Ответы в БД, отображаются на сайте.
- Без WebSockets — периодические запросы.

### 3.9. Отчёты и дашборд (для владельца/менеджера)
- Главная после входа — дашборд с графиками:
  - Выручка за сегодня/неделю/месяц.
  - Заказы по часам (график).
  - ТОП-5 популярных блюд.
  - Соотношение доставка/самовывоз.
  - Среднее время готовки.
  - Эффективность курьеров (кол-во доставок, среднее время).
- Отчёты за период (выбор дат) — таблица: продажи, скидки, возвраты.
- Данные из таблиц заказов и клиентов.

### 3.10. Учёт склада (ингредиентов)
- Раздел "Склад". Ингредиент: название, единица, остаток, критический минимум.
- Автосписание при создании заказа с пиццей (рецепты). Упрощённо: пицца 30 см — 200г муки, 150г сыра и т.д.; 40 см — пропорционально. Рецепты настраивает менеджер.
- Ручная корректировка остатков (приёмка товара).
- Отчёт по расходу ингредиентов за период.

### 3.11. Роли и права доступа
- **Касир**: создание заказов, редактирование (до готовки), просмотр клиентов, скидки.
- **Повар**: только KDS (отдельная страница), активные заказы, смена статусов (начать готовку, готово).
- **Кур'єр**: свой дашборд (список заказов для доставки, смена статусов).
- **Оператор підтримки**: просмотр всех заказов, чат, поиск по номеру, отмена с причиной.
- **Менеджер**: всё, что у кассира + управление меню, скидками, пользователями (кроме владельца), отчёты.
- **Власник**: полный доступ, включая настройки системы, управление пользователями.
- В демке можно захардкодить тестовых пользователей с разными ролями и страницу входа с выбором роли.

### 3.12. Локализация
- Два языка: украинский (по умолчанию) и русский. Кнопка в шапке, сохранение в `localStorage`.
- Все видимые тексты (включая названия блюд, статусы, сообщения) через `__('key')` из `i18n.js`. Словари частично заполнены, нуждаются в дополнении.
- Чеки печатаются на языке интерфейса.

### 3.13. Печать чеков
- Кнопка "Друк чеку"/"Печать чека" для каждого заказа.
- Чек: номер заказа, дата, блюда с ценами, итог, способ оплаты, скидки.
- `window.print()` (отдельное окно). Фискальные требования не нужны; для красоты — QR-код (заглушка).

## 4. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ
- API в `api/`, `db.php` для SQLite, подготовленные запросы обязательны.
- Фронтенд модульный: раздел CRM = JS-модуль в `js/modules/`. `app.js` — роутинг/инициализация.
- Витрина — SPA на чистом JS (`site/js/app.js`), данные из API CRM.
- `fetch` + JSON.
- KDS — отдельный `kds.html` + `kds.js` (в `js/`), не зависит от `app.html`, доступен по прямому URL (`pizzacrm/kds.html`).
- Чат — таблица `messages`: `id`, `session_id` (или `client_id`), `operator_id`, `message`, `timestamp`, `is_read`.
- БД: добавить поля в существующие таблицы через миграции/прямые SQL-скрипты (отдельный файл `migrate.php`).

## 7. ПРАВИЛА РАБОТЫ ДЛЯ ИИ (ОБЯЗАТЕЛЬНО)
1. **ЗАПРЕЩЕНО** менять существующие CSS-классы, id, HTML-структуру. Новый код — в новые файлы ИЛИ дописывается в конец существующих, без изменения старого кода.
2. **Запрещено** переписывать/рефакторить существующие функции JS. Только добавлять новые и вызывать их.
3. Новые стили — в отдельные файлы (напр. `kds.css`) или инлайн (для KDS). Не менять `app.css`/`style.css`, кроме исправления бага и после согласования.
4. Перед изменениями — показать план (файлы + что конкретно).
5. После каждого изменения — показать diff (2–3 ключевые строки).
6. Использовать существующие функции локализации (`__()`), не хардкодить текст.
7. Не использовать сторонние библиотеки без разрешения (кроме Font Awesome).
8. Все API-запросы асинхронные (fetch), с обработкой ошибок.

## 10. ТЕСТИРОВАНИЕ И КОНТРОЛЬ КАЧЕСТВА
- **Автотесты (smoke):** дополнять `tests/smoke.php`: проверка БД, существование API-эндпоинтов, создание заказа через API, смена статуса, работа локализации.
