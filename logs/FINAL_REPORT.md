## 5. Самооценка

**Что хорошо:**
- Полный цикл «офлайн-заказ → кухня → готов → курьер → доставлено», «сайт → подтверждение → отмена с причиной», «новая пицца → кастомизация → списание склада» работают сквозно (сценарии ТЗ §10).
- Чистый стек без внешних сервисов и библиотек (кроме шрифтов и Web Audio API); SQLite создаётся автоматически.
- Безопасность: PDO, CSRF, rate limit, Origin-проверка, CSP/nosniff, запрет доступа к служебным файлам.
- Адаптив не ломает существующую структуру: вся полировка — в отдельном `css/polish.css`.

**Что можно улучшить:**
- Медиа-запросы сгруппированы в один файл; при росте модулей стоит вынести сетки в отдельные слои.
- Тёмная тема только у KDS; у CRM светлая тема (по ТЗ тёмная тема и не требуется — только KDS).
- Таблицы на мобильных требуют обёртки `.table-wrap` для горизонтальной прокрутки — в существующих модулях обёртки не везде добавлены (не меняли HTML по правилам ТЗ 7.1).

**Риски:**
- Демо-пароль админа `admin-2026` и `ORDER_SITE_KEY` — только для демо; перед продакшеном поменять в `api/config.php` (`BOOTSTRAP_PASS`, `ORDER_SITE_KEY`).
- Данные `data/crm.db` — боевая демо-база; резервная копия в `backup/backup_2026-08-09/`.
